# KJS IMPERATOR Ω — 12-Day Ultra-Turbo Engineering Sprint

**Operating mode:** implementation-first, evidence-gated, branch-first.  
**Target:** a working, integrated staging release candidate by Day 12.  
**Not a promise:** production readiness is conditional on credentials, database access, provider approval, and successful acceptance tests.

## Execution rules
- Work in the two existing repositories; do not merge their responsibilities.
- IMPRRSDOR remains the control plane; KAMILLO-4531 remains the application/cloud plane.
- Implement in vertical slices: UI → API → persistence → worker → telemetry → tests.
- Every slice must have a runnable acceptance test and an honest status.
- No new paid infrastructure, production mutation, or provider activation without owner authorization.
- Preserve the approved frontend; functional fixes must not redesign it.
- No simulated events in production metrics. Test data stays labeled and segregated.

## Definition of done
A feature is complete only when its code is committed, CI is green, a real or controlled staging acceptance test passes, and the observed result is traceable. A branch build is not a production deployment; a configured adapter is not a connected provider; a storyboard is not a rendered film.
